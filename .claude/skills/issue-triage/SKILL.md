# バックログを棚卸しして次の 1 件を決める

$ARGUMENTS

規約と優先度の導出表は `.claude/rules/issues.md` にあります。

## 1. 現状を把握する

```bash
ls management/issues/todo management/issues/progress
grep -H '^priority:\|^urgency:\|^importance:\|^title:' management/issues/{todo,progress}/*.md
```

件数が多い（10 件以上）場合は `issue-agent` に委譲してください。全文を読む必要があり、
root の文脈を圧迫します。少数なら自分で読んで構いません。

## 2. 検査する

| 検査 | 対応 |
|---|---|
| `priority` が導出表と食い違う | **直す**（事実の誤り） |
| 必須セクションの欠落、`status:` の混入、ファイル名の規約違反 | **直す** |
| 状況が変わって緊急度・重要度が合わない | **提案する**（判断なので勝手に変えない） |
| 重複・包含関係にある issue | **提案する**（統合するか、片方を done にするか） |
| `progress/` に長く滞留（`started:` から日数が経っている） | 状況を確認し、todo に戻すか分割するかを提案 |

`progress/` に 3 件以上あるのは黄信号です。並行しすぎていないか確認してください。

## 3. 並べる

**P 昇順 → score 降順 → `created` 昇順（古い方が先）** で全順序を作ります。
`score = 重要度 × 2 + 緊急度`（`xhigh`=4, `high`=3, `medium`=2, `low`=1）。

```
| # | priority | urgency/importance | title | 状態 |
```

## 4. 次の 1 件を選ぶ

原則は**先頭**です。ただし次の場合は先頭を飛ばしてよく、飛ばす理由を明示します。

- 先頭が**不変条件に触れる**（着手前にユーザーの判断が必要）
- 先頭が他の issue の完了を前提にしている
- 先頭の達成条件が曖昧で、そのままでは着手できない（先に issue を直す）

## 5. 報告する

- 全順序の一覧
- 直したもの（フォーマット・優先度の不整合）
- 提案（緊急度・重要度の見直し、統合、分割）— **勝手に適用しない**
- 次の 1 件と、それを選んだ理由

着手するなら `/issue-work` に進みます。
