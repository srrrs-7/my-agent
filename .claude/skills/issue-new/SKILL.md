# issue を起票する

$ARGUMENTS

規約は `.claude/rules/issues.md`、雛形は `management/issues/TEMPLATE.md` にあります。

## 1. 起票すべきか確認する

今のセッションで着手する 1〜2 ファイルの作業なら、起票せずにやってください。
セッション内の手順分解は `TodoWrite` の仕事です。

起票するのは、**着手を先送りする作業**と、**他と優先順位を比べる必要がある作業**です。

## 2. 調べる

`issue-agent` に委譲します。ブリーフィングに含めるもの:

- 何を issue にしたいか（依頼者の言葉のまま）
- 分かっている背景・きっかけ（レビュー指摘の見送り分なら、その指摘の内容）
- 緊急度・重要度の当たりがついているならそれも（最終判断は issue-agent が根拠付きで行う）

影響範囲の調査（どのクレート・設定・ドキュメントに波及するか、不変条件に触れるか）は
issue-agent がリポジトリを検索して埋めます。**依頼者の言葉を写すだけの issue には価値がありません。**

## 3. 確認する

返ってきた内容を root が確認します。特に:

- **As-is / To-be がユーザー視点か。** 実装方針が書かれていたら書き直させる
- **達成条件が検証可能か。** 「ちゃんと動く」が混ざっていないか
- **優先度が表と一致しているか**（`.claude/rules/issues.md` の導出表）
- **不変条件に「あり」が立っていないか。** 立っていたら、その旨をユーザーに伝える

## 4. 報告する

作成したファイルのパス、優先度とその根拠、既存 issue との相対順位を伝えます。

複数起票した場合は、P 昇順 → score 降順 → 作成日昇順で並べて示してください。
