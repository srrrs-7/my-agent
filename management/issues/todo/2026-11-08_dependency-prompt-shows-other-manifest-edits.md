# 依存の承認プロンプトで、依存の増減以外に同じ書き込みが変える箇所も見せる

## As-is（現状）

モデルが依存ファイル（`Cargo.toml`、`package.json` など）を書き換えると、専用の承認プロンプトが
出て、追加・削除される依存の一覧が表示されます。

ところが**依存の一覧が変わる書き込みでは、一覧だけが表示され、同じ書き込みの他の変更は
表示されません。**

- `Cargo.toml` に `+ serde` と同時に `[package] build = "x.rs"` を足しても、プロンプトには
  `+ serde` しか出ない。承認した人は、ビルドスクリプトが有効になったことを知らない
- `package.json` の `scripts` は install フック（`preinstall` / `postinstall` 等）だけを依存として
  扱うので、`test` や `prepare` 以外の任意のスクリプトの書き換えは一覧に出ない
- 依存の一覧が**変わらない**書き込みは変更行で表示されるので、穴は「一覧が変わる書き込みに
  他の変更を混ぜる」場合に限られる

## To-be（あるべき姿）

- 依存の承認プロンプトを見れば、その書き込みでファイルの何が変わるかが全部分かる。
  依存の増減は読みやすい一覧で、それ以外の変更は短い行差分で出る
- 一覧だけを見て承認したら別の変更も通っていた、ということが起きない

## 影響範囲

- **クレート**: `application/src/supply_chain/`（`mod.rs` の記述の組み立て、`lines.rs` の行差分、
  `cargo.rs` / `npm.rs` などのパーサが依存以外の差分を返す必要があるか）、
  `domain/src/model/dependency.rs`（`DependencyChangeDescription` に「その他の変更」を
  持たせるなら型が変わる）、`cli/src/approval.rs`（`dependency_question` の表示と行数上限）、
  `cli/src/notify.rs`（通知に載る要約）
- **不変条件**: なし（承認ゲートが**出るかどうか**の判定は変えない。表示だけ）
- **設定・ドキュメント**: `README.md` §5「依存ファイルの変更」のプロンプト例
- **利用者への影響**: プロンプトが長くなる。行数上限（`approval.rs` の定数）を超える場合の
  省略表示をどうするか

## 達成条件

- [ ] `Cargo.toml` に依存 1 つと `build = "x.rs"` を同時に足す書き込みで、プロンプトに両方が
      出ることを `approval.rs` のテストで固定する
- [ ] `package.json` で依存の追加と install フック以外の `scripts` の変更を同時に行う書き込みで、
      両方が出ることを固定する
- [ ] 依存以外の差分が行数上限を超えたとき、省略されたことと省略した行数がプロンプトに出る
      （黙って切らない）
- [ ] 依存の一覧が変わらない書き込みの表示（変更行）は退行しない
- [ ] `make check` が緑

## 優先度の根拠

依存ゲートの目的は「承認者がビルドで何が実行されるかを知ったうえで承認すること」で、
ビルドスクリプトの有効化が見えないのはその保証の穴です（重要度 `high`）。いつ直しても
コストは変わらず、通常の書き込み承認や `run_command` の承認が別に入る既定の構成では
単独で悪用しにくい（緊急度 `low`）。score 7 → P2。

## メモ

- レビューの修正方向: 依存の一覧 + それ以外の変更の短い行差分。行差分は `supply_chain/lines.rs`
  に既にある「変更行で記述する」経路を流用できる見込み。一覧に出した行を差分から除くかは
  実装時に判断（重複して出ても安全側）
- npm の install フックの一覧は `supply_chain/npm.rs` の先頭。対象を広げる（全 scripts を
  依存扱いにする）方向もあるが、一覧が騒がしくなるので行差分で見せる方が筋がよさそう
