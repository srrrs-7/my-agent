# Anthropic のプロンプトキャッシュで、毎回の反復の費用と待ち時間を下げる

## As-is（現状）

Anthropic を使うと、反復のたびに system プロンプト・ツール定義・それまでの履歴を
**全額の入力トークンとして送り直しています。** 1 ターンで最大 `AGENT_MAX_ITERATIONS`（既定 25）回
往復するので、同じ前置きに何度も課金され、最初の応答までの待ち時間も伸びます。

`/usage` と `-v` には入力・出力のトークン数しか出ないため、キャッシュを入れたとしても
効いているかを確かめる手段がありません。

## To-be（あるべき姿）

- Anthropic 利用時、変わらない前置き（ツール定義・system・それまでの履歴）がキャッシュから
  読まれ、反復を重ねても入力の費用と待ち時間が伸びにくくなる
- `/usage` と `-v` で、キャッシュの書き込み・読み出しのトークン数が見え、効いているかを確かめられる
- OpenAI 互換・Ollama の利用者には何も変わらない

## 影響範囲

- **クレート**:
  - `infrastructure` … `llm/anthropic.rs`。`WireRequest.system` が文字列なのでブロック形式にする、
    ツール定義・メッセージへの `cache_control`、`WireUsage` にキャッシュの読み書き 2 項目
  - `domain` … `TokenUsage` に 2 項目を足す。`total()` / `accumulate()` の意味を決め直す
    （Anthropic の `input_tokens` はキャッシュ分を含まない、と理解している — 要確認）
  - `cli` … `render.rs`（`-v` の行）、`commands/chat.rs`（`/usage`）
  - `application` … 原則変更なし（`Session.usage` は `accumulate` 経由）
- **不変条件**: なし（§5 に沿い、送出 JSON はモックサーバで固定する）
- **設定・ドキュメント**: `README.md` §3（`/usage`）、§4（loop）。無効化スイッチを足すなら §8
- **利用者への影響**: 破壊的変更なし。Anthropic 利用者の費用と待ち時間が下がる

## 達成条件

- [ ] Anthropic へのリクエストで、どこに `cache_control` が付くかをモックサーバで固定する
- [ ] 応答のキャッシュ読み書きのトークン数が `TokenUsage` に載る。項目が欠けた応答でもパースが落ちない
- [ ] `/usage` と `-v` にキャッシュの読み書きが表示される
- [ ] 同じターンの 2 回目以降の反復で前置きがキャッシュから読まれることを、実 API で 1 回確かめ、
      数値をこの issue に残す（手動確認。テストは実モデルを要求しない — §5）
- [ ] OpenAI 互換プロバイダの送出 JSON が変わらない（既存テストがそのまま通る）
- [ ] `make check` が緑

## 優先度の根拠

正しさにもゴール 1〜3 にも影響しない、費用と待ち時間の改善で、ローカルモデルで回す回避策がある
（重要度 `medium`）。ただし `TokenUsage` の形を変えるので、トークンを数える評価ハーネス（D）より前に
決めておくと手戻りがなく、TODO ツールが計画をどこに差し込むかもキャッシュの効き方を左右する
（緊急度 `medium`）。score 6 → P2。

## メモ

- **設計確認中。** ブレークポイントの置き場所、TTL、無効化スイッチの要否
- ブレークポイント数の上限、最小キャッシュ長、TTL の選択肢、価格は**着手時に公式ドキュメントで
  確認する**（ここには書かない。記憶で決めない）
- 調査で分かったこと（2026-11-08, issue-agent）:
  - system プロンプトはターン（`AgentLoop::run`）の先頭で 1 回組み立てられ、反復の間は変わらない。
    **ターン内のキャッシュは素直に効く**
  - **ターンを跨ぐと外れうる。** system に `Today` とディレクトリ概要（`fs/context.rs`）が入っており、
    エージェントがファイルを作ると次のターンの system が変わる。そのときツール定義の分は残るが、
    system 以降（履歴を含む）は書き直しになる
  - 履歴が予算に張り付くと（圧縮が無効、または要約に失敗したとき）、`trim_to_budget` が反復ごとに
    先頭を削るので、履歴部分のキャッシュは毎回外れる
  - Anthropic プロバイダは `chat_stream` を実装しておらず既定のフォールバックで動く。usage は
    非ストリーミング応答から読めばよい
  - OpenAI 互換側の自動キャッシュ（`cached_tokens` の表示）は範囲外。必要なら別 issue
